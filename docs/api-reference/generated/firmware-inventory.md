## CompareFirmwareObject

`rack_manager.RackManager/CompareFirmwareObject`

CompareFirmwareObject compares the versions in a proposed firmware manifest with firmware currently installed on caller-supplied nodes. It is read-only and does not download firmware artifacts or start update jobs.

| Property | Value |
| --- | --- |
| Execution | **Synchronous.** The response carries the full result. |
| Target | **Caller-supplied nodes.** The request carries each node's endpoints and credentials, and RMS does not store them. |
| Behavior details | [Operations guide](../../operations/firmware.md) |
| Protobuf reference | [`CompareFirmwareObject`](/rms/api-reference/protobuf-reference/rack-manager/rack-manager/rack-manager-compare-firmware-object) |

**Request:** [`CompareFirmwareObjectRequest`](types-rack-manager.md#comparefirmwareobjectrequest)

| Field | Type | Description |
| --- | --- | --- |
| `config_json` | `string` | Proposed JSON firmware manifest |
| `firmware_type` | `string` | Artifact channel/profile, e.g. "dev" or "prod" |
| `nodes` | [`NodeSet`](types-rack-manager.md#nodeset) | Caller-supplied node connection details. A concrete NodeInfo.type takes precedence; NodeInfo.node_descriptor is used to resolve the node type when type is unspecified. |
| `component_filters` | map of `int32` to [`FirmwareObjectComponentFilter`](types-rack-manager.md#firmwareobjectcomponentfilter) | If non-empty, compare only listed node types and components. An empty component list for a listed node type selects all eligible components. |
| `node_descriptor_component_filters` | repeated [`NodeDescriptorFirmwareObjectComponentFilter`](types-rack-manager.md#nodedescriptorfirmwareobjectcomponentfilter) | Descriptor filters are resolved to node types and supplement component_filters. A component_filters entry wins when both selectors resolve to the same node type. |

**Response:** [`CompareFirmwareObjectResponse`](types-rack-manager.md#comparefirmwareobjectresponse)

| Field | Type | Description |
| --- | --- | --- |
| `response` | [`NodeBatchResponse`](types-rack-manager.md#nodebatchresponse) | - |
| `object_id` | `string` | - |
| `matches_manifest` | `bool` | True only when every requested node succeeds and fully matches |
| `nodes` | repeated [`NodeFirmwareManifestComparison`](types-rack-manager.md#nodefirmwaremanifestcomparison) | - |

**Errors:** Refer to [Conventions](../conventions.md#error-handling) for how RMS reports failures.
