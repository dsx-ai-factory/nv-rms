## BatchResetSwitchFactoryDefault

`rack_manager.RackManager/BatchResetSwitchFactoryDefault`

BatchResetSwitchFactoryDefault submits asynchronous NVOS factory resets. All switches in the request use the same domain for NVUE mTLS material. Returns a parent job ID. Use GetJobStatus with child job states to track per-node progress. Unlike the SDN reset, this wipes NVOS configuration back to factory defaults.

A per-node job completes once the switch has rebooted after the reset and is reachable again via the default login; the factory default password is preserved, not rotated. If the supplied switch credentials do not work, RMS falls back to the factory default password to perform the reset, without assuming a switch was already reset just because the default login works. Set allow_ssh_fallback to permit reset submission over SSH when the reset cannot be submitted through NVUE. This fallback is disabled by default.

<Warning>
This operation is destructive. It wipes NVOS configuration.
</Warning>

## UpdateSwitchSystemPassword

`rack_manager.RackManager/UpdateSwitchSystemPassword`

UpdateSwitchSystemPassword initiates asynchronous OS-level password updates for a specific user on a caller-supplied list of switch nodes. The caller supplies both the current password and desired next password so retries can resume after a partial failure. Returns a parent job ID in response.job_id; use GetJobStatus to track progress.

<Warning>
The per-node results in the response report job admission only. Poll the jobs to learn whether each password change succeeded. The request sets only the new password for `username` and takes no current password. RMS reaches each switch with the credentials in that node's endpoint, and those credentials can belong to a different user than `username`. On a retry, RMS probes `password` to detect an earlier partial success.
</Warning>

## BatchCollectSwitchSpdmAttestationEvidence

`rack_manager.RackManager/BatchCollectSwitchSpdmAttestationEvidence`

BatchCollectSwitchSpdmAttestationEvidence synchronously generates and retrieves fresh SPDM evidence from caller-supplied switch trays.

| Property | Value |
| --- | --- |
| Execution | **Synchronous.** The response carries the full result. |
| Target | **Caller-supplied nodes.** The request carries each node's endpoints and credentials, and RMS does not store them. |
| Behavior details | [Operations guide](../../operations/switch-management.md) |
