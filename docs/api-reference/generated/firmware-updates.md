# Firmware Updates

Start firmware updates on one node, many nodes, or from a firmware object.

| RPC | Execution | Summary |
| --- | --- | --- |
| [`UpdateFirmware`](#updatefirmware) | Asynchronous, one job | UpdateFirmware initiates a firmware update on a specific node asynchronously. |
| [`BatchUpdateFirmwareByNodeType`](#batchupdatefirmwarebynodetype) | Asynchronous, parent and child jobs | BatchUpdateFirmwareByNodeType initiates firmware updates on all nodes of a specific type in a rack asynchronously. |
| [`BatchUpdateFirmware`](#batchupdatefirmware) | Asynchronous, parent and child jobs | BatchUpdateFirmware initiates firmware updates on a specified list of nodes asynchronously. |
| [`ApplyStoredFirmwareObject`](#applystoredfirmwareobject) | Asynchronous, parent and child jobs | ApplyStoredFirmwareObject resolves stored firmware targets and starts firmware updates for supplied nodes. |

For definitions of execution modes and job polling, refer to [Async jobs](../async-jobs.md).

## UpdateFirmware

`rack_manager.RackManager/UpdateFirmware`

UpdateFirmware initiates a firmware update on a specific node asynchronously. Returns a job ID immediately. Use GetFirmwareJobStatus to track progress. Works for all node types (compute, powershelf, switch).

| Property | Value |
| --- | --- |
| Execution | **Asynchronous, one job.** The response returns a job ID and the work continues after the call returns. |
| Job tracking | Poll [`GetFirmwareJobStatus`](utility-jobs.md#getfirmwarejobstatus) with the job ID in `job_id`. |
| Target | **Registered inventory.** Reads or changes nodes and racks stored in RMS inventory. |
| Behavior details | [Operations guide](../../operations/firmware.md) |
| Protobuf reference | [`UpdateFirmware`](/rms/api-reference/protobuf-reference/rack-manager/rack-manager/rack-manager-update-firmware) |

**Request:** [`UpdateFirmwareRequest`](types-rack-manager.md#updatefirmwarerequest)

| Field | Type | Description |
| --- | --- | --- |
| `node_id` | `string` | Target node identifier |
| `filename` | `string` | Single firmware filename (used when firmware_targets is empty) |
| `target` | `string` | Single Redfish target URI (used when firmware_targets is empty) |
| `activate` | `bool` | Whether to immediately activate the firmware after installation |
| `rack_id` | `string` | Rack containing the target node |
| `firmware_targets` | repeated [`FirmwareTarget`](types-rack-manager.md#firmwaretarget) | Multiple (target, filename) pairs for batch component updates |
| `force_update` | `bool` | Force the BMC to accept the firmware even if it's a downgrade |

**Response:** [`UpdateFirmwareResponse`](types-rack-manager.md#updatefirmwareresponse)

| Field | Type | Description |
| --- | --- | --- |
| `status` | [`ReturnCode`](types-rack-manager.md#returncode) | RETURN_CODE_SUCCESS if update completed, RETURN_CODE_FAILURE otherwise |
| `message` | `string` | Human-readable status or error message |
| `error_code` | [`FirmwareUpdateError`](types-rack-manager.md#firmwareupdateerror) | Detailed error code for troubleshooting |
| `job_id` | `string` | Job ID for async operations (use with GetFirmwareJobStatus to track progress) |

**Errors:** Refer to [Conventions](../conventions.md#error-handling) for how RMS reports failures.

## BatchUpdateFirmwareByNodeType

## BatchUpdateFirmware

`rack_manager.RackManager/BatchUpdateFirmware`

BatchUpdateFirmware initiates firmware updates on a specified list of nodes asynchronously. Each node is identified by its NodeInfo. Separate firmware targets are provided for compute trays, switch trays, and power shelves, and the appropriate target is applied to each node based on its node type. Returns a parent job ID for tracking overall batch status, along with individual node job IDs. Use GetFirmwareJobStatus to track progress.

| Property | Value |
| --- | --- |
| Execution | **Asynchronous, parent and child jobs.** The response returns a parent job ID and the work continues after the call returns. |
| Job tracking | Poll [`GetFirmwareJobStatus`](utility-jobs.md#getfirmwarejobstatus) with the job ID in `response.job_id`. Per-node child job IDs are in `jobs`. |
| Target | **Caller-supplied nodes.** The request carries each node's endpoints and credentials, and RMS does not store them. |
| Behavior details | [Operations guide](../../operations/firmware.md) |
| Protobuf reference | [`BatchUpdateFirmware`](/rms/api-reference/protobuf-reference/rack-manager/rack-manager/rack-manager-batch-update-firmware) |

**Request:** [`BatchUpdateFirmwareRequest`](types-rack-manager.md#batchupdatefirmwarerequest)

| Field | Type | Description |
| --- | --- | --- |
| `nodes` | [`NodeSet`](types-rack-manager.md#nodeset) | Nodes to update |
| `firmware_targets` | map of `int32` to [`FirmwareTargetList`](types-rack-manager.md#firmwaretargetlist) | Firmware targets keyed by NodeType enum value |

## ApplyFirmwareObject

`rack_manager.RackManager/ApplyFirmwareObject`

ApplyFirmwareObject ingests a firmware object from JSON, downloads required artifacts, resolves firmware targets, and starts firmware updates for supplied nodes.

RMS treats the ingested firmware object as ephemeral for this request. It uses access_token only for artifact download and does not persist the token or object.

| Property | Value |
| --- | --- |
| Execution | **Asynchronous, parent and child jobs.** The response returns a parent job ID and the work continues after the call returns. |
| Job tracking | Poll [`GetFirmwareJobStatus`](utility-jobs.md#getfirmwarejobstatus) with the job ID in `response.job_id`. Per-node child job IDs are in `jobs`. |
| Target | **Caller-supplied nodes.** The request carries each node's endpoints and credentials, and RMS does not store them. |
| Behavior details | [Operations guide](../../operations/firmware.md) |
| Protobuf reference | [`ApplyFirmwareObject`](/rms/api-reference/protobuf-reference/rack-manager/rack-manager/rack-manager-apply-firmware-object) |

| Field | Type | Description |
| --- | --- | --- |
| `rack_id` | `string` | - |

| `access_token` | optional `string` | Used only for artifact download; RMS does not persist it |
| `firmware_type` | `string` | "dev" or "prod" |
| `hardware_type` | `string` | - |
