## ExecuteColdReboot

`rack_manager.RackManager/ExecuteColdReboot`

ExecuteColdReboot orchestrates the full DGX GB200 rack COLD reboot sequence on caller-supplied nodes (no inventory registration required): gracefully shut down the compute trays over BMC, power off the power shelves, wait for capacitor discharge, power the shelves back on, wait for the compute/switch tray BMCs and switch NVOS to come up, then power on the compute nodes. Returns a coordinator job ID immediately; poll GetJobStatus on it: while running, execution_state is RUNNING and state_description reports the current stage by its rack-reboot runbook step number(s) (e.g. "Rack reboot step 7-8: ..."); on completion or failure the full per-stage stage timeline is written to result_json. Runbook steps 9 (switch fabric provisioning) and 13 (post-reboot host/GPU verification) are out of scope. The sequence is fail-fast with no automated rollback.

<Warning>
The sequence stops at the first failed stage and does not roll back. The response `job_id` identifies the coordinator job.
</Warning>

| Property | Value |
| --- | --- |
| Execution | **Asynchronous, one job.** The response returns a job ID and the work continues after the call returns. |
| Job tracking | Poll [`GetJobStatus`](utility-jobs.md#getjobstatus) with the job ID in `response.job_id`. |
| Job result | `result_json` in the job status holds the full per-stage timeline of the reboot sequence, written on completion or failure. |
| Target | **Caller-supplied nodes.** The request carries each node's endpoints and credentials, and RMS does not store them. |
| Behavior details | [Operations guide](../../operations/power-control.md) |
| Protobuf reference | [`ExecuteColdReboot`](/rms/api-reference/protobuf-reference/rack-manager/rack-manager/rack-manager-execute-cold-reboot) |

**Request:** [`ExecuteColdRebootRequest`](types-rack-manager.md#executecoldrebootrequest)

| Field | Type | Description |
| --- | --- | --- |
| `nodes` | [`NodeSet`](types-rack-manager.md#nodeset) | Participating devices: compute + power-shelf + switch trays (full NodeInfo) |
| `domain` | optional `string` | Optional NVL domain selecting switch mTLS material for the NVOS-readiness probe |
| `prestage_shutdown_floor_seconds` | optional `uint32` | Min wait after issuing the compute graceful shutdown before probing (default 0) |
| `prestage_shutdown_poll_max_seconds` | optional `uint32` | Max wait for compute to power down before the shelves are cut (default 300) |
| `discharge_floor_seconds` | optional `uint32` | Min wait after shelf power-off before probing (default 180) |
| `discharge_poll_max_seconds` | optional `uint32` | Max wait for BMCs to become unreachable (default 600) |
| `bmc_up_floor_seconds` | optional `uint32` | Min wait after shelf power-on before probing (default 120) |
| `bmc_up_poll_max_seconds` | optional `uint32` | Max wait for BMCs to become reachable (default 600) |
| `nvos_hello_backoff_seconds` | optional `uint32` | Base delay for the exponential backoff between switch nvue-hello attempts (default 30) |
| `compute_boot_wait_seconds` | optional `uint32` | Fixed wait for the compute OS to boot after power-on (default 300); the BMC cannot report OS readiness |
| `poll_interval_seconds` | optional `uint32` | Poll cadence for all stages (default 15) |

**Response:** [`ExecuteColdRebootResponse`](types-rack-manager.md#executecoldrebootresponse)

| Field | Type | Description |
| --- | --- | --- |
| `response` | [`NodeBatchResponse`](types-rack-manager.md#nodebatchresponse) | response.job_id is the coordinator job ID for GetJobStatus |

**Errors:** Refer to [Conventions](../conventions.md#error-handling) for how RMS reports failures.
